The short answer

des-k does two things:

  1. It catches your shortcuts before Windows sees them.
  2. It hides the windows on one screen, and shows the ones it saved for the workspace you go to.

To hide a window, des-k asks Windows to cloak it. This is the feature behind Windows' own virtual desktops. A cloak works on one window at a time, so the caller chooses which windows to hide. Windows chooses every window that is not on the new desktop, on all screens. des-k chooses only the windows on the screen under your mouse.

youdes-kWindowswhat des-k remembers

A hidden window is never closed. Its program keeps running: a call goes on, a download goes on. Windows only stops drawing it.

Words used here

Cloak

To hide a window without closing it. Windows stops drawing it; the program keeps running.

Window handle

The number Windows gives each window (HWND). des-k's lists hold these numbers.

Shell

explorer.exe: the taskbar, the desktop, and the part of Windows that manages app windows.

DWM

Desktop Window Manager. The part of Windows that draws every window on the screen.

COM

Windows' way for one program to call objects in another. des-k talks to the shell through it.

Hook

A function that Windows calls when something happens, for example a key press.

Main thread

The one thread in des-k that changes windows. Every other thread only sends it messages.

EDID

The data a monitor reports about itself: its maker, its model and its serial number.

How it works

What happens in one switch?

Every way to switch (a shortcut, a swipe, a jump to workspace 3) ends in one function: switch_to in src/ws.rs.

  1. You press Win+Ctrl+Right. The keyboard hook sees the keys first and swallows them, so Windows never gets the shortcut.
  2. The keyboard thread posts a message to the main thread. It does no slow work itself.
  3. The main thread asks Windows where the mouse is (GetCursorPos) and which screen that is (MonitorFromPoint).
  4. It lists the app windows on that screen: EnumWindows for all windows, then MonitorFromWindow for each one.
  5. It cloaks each of them, bottom window first. Each window handle goes into the list of the workspace you leave. Pinned windows are skipped.
  6. It shows the windows in the list of the workspace you go to, top window first.
  7. If the focused window was just hidden, focus moves to the top window that is now shown.
  8. It shows the indicator and writes the layout to state.txt.
Why bottom first? Hiding the top window first would uncover the windows behind it for a moment. des-k hides from the bottom and shows from the top, so nothing flashes.

A window that fails to show stays in its list. The next switch, a quit or a crash tries again, so no window is forgotten while it may still be hidden.

How it works

How does des-k hide one window?

It makes two calls for each window. One hides the window. The other removes its taskbar button. Both are in src/cloak.rs.

des-kWindows

Windows has a public call to cloak a window (DwmSetWindowAttribute with DWMWA_CLOAK). But it only works on a program's own windows. To cloak the windows of other programs, des-k talks to the shell through COM, on an interface called IApplicationView. Microsoft does not document this interface, so des-k calls each method by its position in the interface, its slot.

StepCallWhat it does
Reach the shellShell::newAsks the shell for its list of app views. A new one for each operation, because explorer can restart.
Find the window's viewGetViewForHwnd, slot 6Gives the IApplicationView of that window.
Check the layoutGetThumbnailWindow, slot 9Must give back the same window handle. If not, des-k stops here.
CloakSetCloak, slot 12DWM stops drawing the window. DWMWA_CLOAKED then reads 2 for it.
RemembermarkAdds the window to a small list of its own, which the crash handler can always read.
TaskbarDeleteTab, AddTabRemoves the taskbar button on hide and adds it back on show. A cloak alone leaves the button.
 
pub fn hide(&self, hwnd: HWND, hide: bool) -> Result<()> {
    self.set_cloak(hwnd, hide)?;
    mark(hwnd, hide);
    unsafe {
        if hide { self.1.DeleteTab(hwnd) } else { self.1.AddTab(hwnd) }
    }
}
A Windows update can move the slots.So des-k checks the layout before every cloak. If the check fails, it does not call SetCloak at all, and the tray shows a warning that hiding stopped working.

How it works

How is it per screen?

des-k does not use Windows' virtual desktops at all. It keeps its own small record for each screen:

struct Monitor {
    active: usize,
    hidden: Vec<Vec<isize>>, // one per workspace: the windows it hid, top of z-order first
    // ...
}
what des-k remembersthe workspace on screen now
  • A workspace remembers only the windows des-k hid there.
  • The workspace on screen has no list. It is simply every window you can see on that screen now.
  • So a new window needs no tracking. A window you drag to another screen needs none either.
  • A switch reads and changes the lists of one screen only.

Which windows does a switch hide?

app_window in src/ws.rs decides. It keeps about the same windows as Alt+Tab shows. A switch then also skips pinned windows.

A window is left alone when itWhy
is not visible, or is already cloakedThere is nothing to hide.
is owned by another windowA dialog goes with its owner.
is a tool window, or has no titleThese are helper windows, not apps.
is the desktop or a taskbardes-k never hides the shell.
belongs to des-kIts settings page must never be hidden by a switch.
is pinnedA pinned window stays on every workspace of its screen.
des-k only shows windows it hid itself. A cloaked window looks the same whether des-k hid it, it sits on another Windows desktop, or it is a sleeping Store app. So des-k trusts its own lists, never the cloak alone.

How it works

How does des-k know your screens?

It asks Windows, then asks each monitor who it is. This is screen_ids in src/ws.rs.

What des-k needsCall
The list of screensEnumDisplayMonitors
Position, size, work area, main display or notGetMonitorInfoW
The name you know ("DELL U2720Q"), laptop panel or notQueryDisplayConfig
The monitor's own idIts EDID, read from the registry through SetupAPI (edid_id in src/restore.rs)

The id is made from the EDID: maker, product code and serial number. A laptop's own panel gets the id internal. Two equal monitors with no serial number get #1 and #2, left to right.

Windows' own names (DISPLAY1, DISPLAY2) can swap when you dock, undock or change a cable. The EDID does not change. So each monitor keeps its own workspaces, wherever you plug it in.

What happens when a screen is unplugged?

  • des-k checks the screens once a second, and when Windows reports a display change.
  • A screen must be missing for 10 checks in a row before it counts as gone. Screens drop out for a moment on wake from sleep.
  • Then its windows fold onto the main display. Hidden windows stay hidden, in the workspace with the same number.
  • Each window gets an "away" record: its home screen, its workspace and its position.
  • When the screen comes back and the layout is calm, each window goes home to its old place.

How it works

Which threads does it have?

One rule keeps des-k simple: only the main thread changes windows. Every other thread only tells it what happened.

des-kWindows
ThreadWhat it doesWhat it never does

The window lists sit behind one lock. Callbacks from Windows, such as "a window took focus", never touch them. They only post a message, and the main thread handles it on its next turn.

How it works

How are your shortcuts caught?

des-k installs a low level keyboard hook (SetWindowsHookExW with WH_KEYBOARD_LL). Windows then calls des-k for every key, before any program gets it.

  • A match is swallowed. The hook returns 1, so the key goes no further. Any other key is passed on with CallNextHookEx.
  • The Start menu stays closed. After a swallowed Win or Alt shortcut, des-k sends one unused key (0xE8). Windows then thinks Win was part of a combination and opens nothing.
  • des-k ignores its own keys. Every key des-k types carries a marker in dwExtraInfo, and the hook skips those.
  • The hook is watched. Windows can remove a hook without telling the program. des-k also counts keys through Raw Input. Every 5 seconds it compares: 3 or more keys seen and none heard by the hook means the hook is gone, and des-k installs it again.

The touchpad works the same way. Its thread reads every precision touchpad through Raw Input, follows the fingers, and posts the gesture. des-k acts on three and four finger gestures only while Windows' own gestures for them are off.

How it works

What if a hidden window gets focus?

You click a hidden window's taskbar button, or an app brings its window to the front. Focus would then sit in a window you cannot see. So des-k follows: it switches that window's screen to its workspace.

  1. Windows reports "this window is now in front"
  2. The callback posts a message
  3. The main thread finds the window in a list
  4. That screen switches to that workspace

Apps grab focus at bad moments, so follow in src/ws.rs has guards:

des-k does not follow whenWhy
the window no longer has focusdes-k's own switch may have moved focus on since.
that screen left this workspace less than 1 second agoWindows can hand focus to a window while it is being hidden. Going back would undo your switch.
that screen followed less than 1 second agoSome apps keep grabbing focus.
an app rule hid the window and it was never shownThe app took focus as it opened. You did not ask for it.

What is saved, and where?

Everything is in %LOCALAPPDATA%\des-k\.

FileWhat it holds
state.txtThe layout: each screen, its shown workspace, and every window with its place. Written after every change.
settings.tomlYour settings. des-k checks it once a second and applies changes live.
des-k.logWhat des-k did and why. It names a window by its program, never by its title. At 5 MB it starts fresh.
wallpapers\The pictures a workspace can show.

state.txt is plain text, one line per thing. The first letter says what the line is:

LineWhat it records
LThis sign in to Windows: its id and time.
MA screen: its id, the workspace it shows, its work area and its name.
WA hidden window: its screen, workspace, window handle, process id and position.
V, PA visible window, and a pinned one.
AA window away from its unplugged home screen, and where it goes back to.

Each window line also carries the window's program, class and title. des-k needs them to know a window again after a reboot.

What happens at start?

  1. des-k looks for its own indicator window. If one exists, a copy is already running, and this one exits.
  2. It loads settings.toml, then state.txt.
  3. It installs the crash handler, starts the keyboard and touchpad threads, and shows the tray icon. des-k hides nothing new before every way out is in place.
  4. Same sign in (des-k was restarted, updated or killed): the saved windows still exist. des-k adopts a window only if it has the same window handle and process id, and is still cloaked.
  5. New sign in (a reboot): every window handle is new. des-k matches each reopened window to a saved one by program, class and title, and hides it on its old workspace. If the match is not clear, the window stays visible.

How it works

What happens when des-k stops?

A hidden window that nobody shows again would be lost to you. So every way out shows every hidden window first.

How it stopsWhat happens
Tray → Quit, or des-k --quitEvery hidden window is shown, then des-k exits.
Ctrl+C in a developer consoleThe same.
A crash (a Rust panic)The panic hook shows every window, then ends the process. If the crash happened in the middle of a switch, the hook uses the separate list that cloak.rs keeps.
A hard killWindows stay hidden, but state.txt is kept. The next start adopts them. des-k --quit with no des-k running shows them.
Explorer restartsThe new taskbar can list hidden windows again, and a cloak may be gone. On its next 1 second check, des-k hides every window in its lists again.

How it works

Why does it run as admin?

Windows does not let a normal program hear keys that go to an admin window. Without admin, your shortcuts would stop each time Task Manager or an admin terminal has focus. So the installed des-k starts as admin, from a task that runs when you sign in.

A program that runs as admin and hears every key must be careful. des-k keeps these rules:

  • No network on its own. des-k goes online only when you click Check for updates or Install in the tray.
  • An update must match its checksum. des-k runs a downloaded setup only if its SHA-256 matches the release's SHA256SUMS.txt.
  • Settings can never start a program. Any program running as you can write to %LOCALAPPDATA%\des-k. So nothing there may name a program to run or code to load.
  • The log is safe to share. It names a window by its program. It never holds a window title or a workspace name.

The setup also offers Install for me only, for accounts without admin. That copy runs without admin on purpose, so its shortcuts stop while an admin window has focus. SECURITY.md has the full list of promises and how to report a problem.
